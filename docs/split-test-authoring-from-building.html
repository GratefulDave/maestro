Splitting test authoring from building

Recommend, do not implement. Building this is maestro-plan.v3 and orphans paused run run-c8910572828c4f5bb5c60c0582dd4be5. Written 2026-08-20 beside §19 M35. Source: split-test-authoring-from-building.md.

The hole

In cmo-consolidation-l-r7 each agent node owns both the production module and the test file its own gate counts. min_cases counts cases, not assertions. Nine tests that reimplement the module go green. Phase 1 detects that after the fact: revert everything the gate did not select, re-run, require failure. It cannot see a node whose every written path is the gate selector.

The proposal

spec nodebuild node
idlane-…-speclane-…
needs—the spec node
outputsthe test filethe production module
post-gatecollects ≥ min_cases, all failcollects ≥ min_cases, all pass

The build node cannot write the test. §8.3 already refuses undeclared writes. The pre-node gate on the build node becomes red because behaviour is missing, not because the file is missing.

Schema cost

A spec node is not agent (wrong gate predicate) and not code (it launches an agent). New NodeKind.SPEC means maestro-plan.v3. v2 stays runnable. Residual: nine assert False still satisfy the spec predicate.

Recommendation

  1. Do not implement until r7 has run under Phase 1.
  2. If needed: v3 + SPEC + scoped evidence chain + uniform projection, as one change.
  3. Keep v2 runnable. Do not invent R1’s counter without a measured case.
Design note only. Not a shipped contract.
