Declaring what is watched, and what the check says

Two template copies of the ADW runtime are held together by tests/test_template_parity.py: this repo’s .claude/skills/sssf/templates/adws/ and the-library’s skills/sssf/templates/adws/.

Every other copy is a deployment. tests/test_deployment_parity.py watches those if you declare them. Markdown source: deployment-drift.md.

Turning it on

Write <repository>/.maestro/deployments.json. Nothing is hardcoded. MAESTRO_DEPLOYMENT_REGISTRY overrides the path.

{
  "deployments": [
    { "name": "lexgenius-pipeline", "root": "../../lexgenius-pipeline/adws" },
    { "name": "lexgenius", "root": "../../lexgenius/adws",
      "note": "reconciled by hand; see issue #71" }
  ]
}
FieldMeaning
nameLabel in every report. Unique.
rootADW runtime directory. Absolute, or relative to the registry file.
pinnedPaths this deployment owns. Held out of comparison and named. Optional.
noteFree text. Optional.
  • A misspelled key fails the suite. It is not ignored.
  • The registry is read from the main working tree, not a lane worktree, so relative roots resolve.
  • No registry, or a declared checkout missing on this machine, skips and names the path it looked for.

Three findings, three actions

  1. Exists on one side only. A deletion, not an edit. Own field in the report.
  2. Template is ahead. Deployment is older. Mirror repairs it; the failure prints the command.
  3. Deployment is ahead. No safe automatic command. Either promote the work, discard with --overwrite-ahead after reading the digest, or pin it.

Pinning is the only answer this mechanism can express. A pinned file stops being compared and starts being named.

The write stays explicit

The check never mirrors. Nothing in this repository writes into a deployment automatically.
python3 tools/runtime_sync.py check-deployments <template> [--registry FILE]
python3 tools/runtime_sync.py check  <template> <deployment> [--pin PATH ...]
python3 tools/runtime_sync.py mirror <template> <deployment> --apply --commit

--apply --commit copies with a sha256 assertion per file, stages only the paths it wrote, and commits. It never git add -A. It refuses if the destination has uncommitted work in a file it would overwrite. It never pushes. The commit message names every hold-out, refusal, and discard.

Detection is automatic. The write is an operator command.
