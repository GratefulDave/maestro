Contract / plan authoring

From a source document to an executable plan

Planning skills (deep-interview, arch-brownfield, planf3, arch-review) produce one approved executable plan. Maestro does not run plan gate, plan review, plan ship, plan finalize, or bootstrap. Execution is uv run adws/maestro.py run start|resume|amend|status. Durable authority after start is lane_state.stage plus immutable artifacts.

source documents ──► approved executable plan ──► run start --repo … --main-ref …
   (audit, interview,     compiler: schema, DAG,         nine-stage factory
    arch)                 ownership, acceptance

Supporting a new kind of input means citing that document in the approved plan, not adding an adapter. Markdown source of this page: plan-authoring.md (historical notes may still mention planctl).

The projection boundary

The plan compiler validates only objective properties. It refuses anything it cannot execute. The table below is authoring shape, not operator verbs.

Contract elementBecomes
schema_versionfrozen plan schema
lanes[].idstable lane identity
lanes[].needssorted dependencies and topological integration order
lanes[].outputsnormalized declared paths with one owner each
lanes[].acceptancepublic behavioral acceptance criteria
lanes[].speccanonical lane specification and spec_digest
  • Repair means a new approved plan revision and run amend. Never edit an approved plan in place.
  • An architecture-only document is not a run. It is an anchor for planning skills.

Single repository

  1. deep-interview, arch-brownfield, planf3, and arch-review — one approved executable plan.
  2. uv run adws/maestro.py run start <approved-plan> --repo <target-worktree-root> --main-ref <ref> — creates the run, PLANNED lanes, and integration ref.
  3. uv run adws/maestro.py run resume <run-id> — next incomplete stage from the last immutable artifact.
  4. uv run adws/maestro.py run amend <approved-plan> --run <run-id> — only verb that may apply a PLAN_AMENDMENT.
  5. uv run adws/maestro.py run status <run-id> — derived from durable rows after fingerprint revalidation.
Deployment copy only. Invoke adws/maestro.py from the stamped product repository. Template-source run creation refuses RUN_REPOSITORY_MISMATCH. There is no bootstrap or planctl operator path.

Verifier commands

Public acceptance is behavioral. Private tests are authored, reviewed, and sealed before building. Sealed bytes stay in the vault under runtime_state_root; the builder never receives private source.

  • Pass real argv, never npm test / make test.
  • Exactly one lane owns a path (SINGLE_OUTPUT_OWNER).
  • Playwright and Cypress cannot be public gates today.

Private tests are sealed, then hidden

Shipped factory: test author → test review (PASS/REVISE) → SEALED_TEST_BUNDLE in the hidden vault → builder → code review. Private source, fixtures, selectors, and expected literals do not leak to the builder. Code review runs sealed tests and emits a public result summary plus redacted findings. Historical test_visibility / v5 notes live on hidden-tests-design.

Outputs are write permission

Exactly one lane may own a path. Ask: could an agent satisfy this instruction by changing only these files? If not, the lane will fail review. That judgment is a planning-skill / run amend problem, not maestro plan review.

Review rejection

A reviewer REVISE artifact returns the lane to WRITING_TESTS or BUILDING with actionable redacted findings. There is no repair chain, attempt identity, or run convergence verb. Resume is the next incomplete stage from the last immutable artifact.

Several repositories

The proven slice is two dependent lanes in one target worktree. Multi-repo workspace manifests are not the factory operator surface.
