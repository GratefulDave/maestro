From a source document to an executable plan

Maestro executes maestro-plan.v2. It does not read audits, interviews, or HTML specs. Those documents enter only as hash-pinned source_artifacts inside a plan-contract.v1 IR that already has a bound HTML view and a PASS review receipt.

source documents ──► plan-contract.v1 Plan IR  ──► maestro-plan.v2 ──► run
   (audit HTML,       + extensions.maestro          (projection)
    interview,        + bound HTML view
    arch deck)        + PASS review receipt

Supporting a new kind of input never means a new adapter. It means citing that document as a source in a plan. Markdown source of this page: plan-authoring.md.

The projection boundary

plan_contract_ingress.author_from_plan_contract verifies the receipt against the exact IR bytes, then projects. It refuses anything it cannot execute.

  • Repair means re-render, re-validate, new receipt. Never edit an approved IR in place.
  • An architecture plan is refused (ARCHITECTURE_NOT_EXECUTABLE). It is an anchor, not a run.

Single repository

  1. /arch-review <master-spec> — architecture IR, HTML view, review receipt under .maestro/.
  2. /plan-brownfield "what to build" <master-spec> — one work package per reviewable unit, each with extensions.maestro.
  3. maestro plan gate <plan-name> — author renders, validates, mutates. Refuses if the reviewer HMAC is in the environment.
  4. maestro plan review <plan-name> — a second person, reviewer key, no model. Receipt bound to ir_sha256.
  5. maestro plan ship <plan-name> — project to maestro-plan.v2, validate, finalize. Finalize is deterministic (maestro-deterministic.v1). No pane reviewer.
v1 plans do not run. _load_runnable_plan allowlists maestro-plan.v2. Re-ship from the same IR and receipt. There is no upgrade function.

Bootstrap writes two files: maestro.env (author) and reviewer-hmac.env (reviewer only). Source the first. Maestro never reads the second on the supported path.

# maestro plan gate
planctl render / validate / mutate

# maestro plan review  — reviewer key, never author key
planctl review
planctl validate --require-approved

# maestro plan ship
maestro plan author --from-plan-contract …
maestro plan validate
maestro plan finalize

Every planctl call uses --repo-root . so IR paths in .maestro/ can cite repo-relative sources without ...

Verifier commands

Gate.runner is Literal["pytest", "vitest"]. Maestro counts executed cases against min_cases. A shell script, Makefile, psql, or curl is maestro.command.

  • Pass real argv, never npm test / make test.
  • One verifier per lane (maestro.lane_gate otherwise).
  • Playwright and Cypress cannot be gates today.

Outputs are write permission

Exactly one lane may own a path (SINGLE_OUTPUT_OWNER). Ask: could an agent satisfy this instruction by changing only these files? If not, the lane will burn its review budget between “instruction not met” and “undeclared write.” Finalize no longer judges that; a person must, at maestro plan review.

Review rejection

Review rejection records findings and one handoff, then returns to the retained builder and worktree. Review is not the repair trigger; SEMANTIC plus a proven output SHA still opens a repair chain. maestro run convergence reports findings per attempt and will not call a live run finished.

Several repositories

No multi-repo Plan IR. Each repo finishes to a PASS finalization receipt, then a maestro-workspace.v1 manifest binds participation and order.

maestro workspace author --from workspace-draft.json --out workspace.json --root .
maestro workspace validate --manifest-file workspace.json
